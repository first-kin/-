## 2. 前端选型：Vue 3 全家桶

| 选型 | 理由 |
| ---- | ---- |
| Vue 3 + Composition API | 组合式函数便于封装登录鉴权、分页请求等复用逻辑；`<script setup>` 语法简洁 |
| Vite | 开发热更新极快，`npm run build` 产物为纯静态文件，可直接交给 Nginx 托管 |
| Element Plus | 组件齐全（表格、分页、表单校验、弹窗），与学生管理类系统需求高度匹配 |
| Pinia | Vue 3 官方推荐状态库，用于保存 Token、用户角色等全局状态 |
| Vue Router | 前端路由 + 导航守卫（未登录跳转、按角色过滤菜单） |
| Axios | 拦截器统一携带 Token、统一处理错误码 |
| ECharts | 需求分析中"数据统计模块"的饼图/柱状图 |

**前端关键技术决策：**
- Token 存储于 `localStorage`，请求头格式：`Authorization: Bearer <token>`
- 开发期通过 Vite `server.proxy` 把 `/api` 代理到后端 `http://localhost:8080`，规避跨域
- 菜单按角色（admin / teacher / student）动态渲染

## 3. 后端选型：C++17 + Drogon

### 3.1 为什么选 Drogon

C++ 并非传统 Web 后端首选语言，但 Drogon 是目前**生态最成熟、社区最活跃**的 C++ Web 框架，选它而非其他框架的理由如下：

| 框架 | 特点 | 是否推荐 |
| ---- | ---- | -------- |
| **Drogon** | 全功能：HTTP 路由、中间件、ORM、WebSocket、异步 IO；文档完善；有配套脚手架 `drogon_ctl` | ✅ **推荐** |
| Crow | 轻量易上手，但无 ORM，中间件生态弱 | 备选 |
| Oat++ | 结构清晰，但社区活跃度下降 | 不推荐 |
| cpp-httplib | 单头文件库，只适合做静态服务/极简接口 | 不推荐 |

### 3.2 Drogon 提供的关键能力（与需求的对应）

| Drogon 能力 | 对应系统需求 |
| ----------- | ------------ |
| RESTful 路由注册 | 所有业务接口（学生/课程/成绩 CRUD） |
| 内置 JSON（基于 nlohmann/json） | 统一响应格式 `{code, msg, data}` |
| `HttpFilter`（过滤器） | JWT 登录校验、角色权限拦截（对应 AUTH-06） |
| Drogon ORM + MySQL 驱动 | 数据库访问，防 SQL 注入（参数化查询） |
| 内置连接池 | 数据库连接池（性能要求） |
| 异步非阻塞 IO（epoll/IOCP） | 200 人并发在线（非功能需求） |

### 3.3 后端分层结构

```
backend/
├── CMakeLists.txt
├── main.cpp                  # 启动入口
├── controllers/              # 控制器层：接收请求、参数校验、返回 JSON
│   ├── AuthController.cpp        # 登录/登出
│   ├── StudentController.cpp     # 学生管理
│   ├── CourseController.cpp      # 课程管理
│   ├── ScoreController.cpp       # 成绩管理
│   └── NoticeController.cpp      # 通知公告
├── services/                 # 业务层：核心业务逻辑（事务、校验规则）
├── filters/                  # 过滤器：JwtFilter（鉴权）、RoleFilter（RBAC）
├── models/                   # Drogon ORM 生成的实体类
└── config/                   # 应用配置（app.json：端口、数据库连接、密钥）
```

### 3.4 关键第三方库

| 库 | 用途 | 说明 |
| ---- | ---- | ---- |
| jwt-cpp | 签发/校验 JWT | Login 时签发含 `uid`、`role` 的 Token，过滤器统一校验 |
| libbcrypt | 密码加密 | 对应需求 AUTH-01，绝不明文存储 |
| nlohmann/json | JSON 序列化 | Drogon 已内置，无需单独引入 |

### 3.5 构建与依赖管理（Windows 环境）

```bash
# 1. 安装 vcpkg 并安装依赖（Windows 下推荐 MSVC）
vcpkg install drogon jwt-cpp libbcrypt

# 2. CMake 引入依赖（CMakePresets.json 中指定 toolchain）
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=%VCPKG_ROOT%/scripts/buildsystems/vcpkg.cmake
cmake --build build --config Release

# 3. 运行（默认监听 8080 端口）
./build/backend.exe
```

> 备选：也可用 WSL2（Ubuntu）+ GCC 开发，依赖安装更顺畅（`apt install` + 源码编译 Drogon），部署时与 Linux 服务器环境一致。

## 4. 数据库选型：MySQL 8.0

| 决策点 | 选择 | 理由 |
| ------ | ---- | ---- |
| 存储引擎 | InnoDB | 支持事务（成绩录入需要事务保证）与外键 |
| 字符集 | utf8mb4 | 完整支持中文及特殊字符 |
| 访问方式 | Drogon ORM（参数化查询） | 天然防 SQL 注入 |
| 连接管理 | Drogon 内置连接池 | 复用连接，降低开销 |
| 备份 | `mysqldump` 定时任务 | 满足"每日备份"非功能需求 |

表结构设计与《需求分析.md》第 3 节对应：`users`、`students`、`teachers`、`departments`、`classes`、`courses`、`scores`、`notices`、`logs`，核心表将在《数据库设计》文档中详细给出。

## 5. 前后端交互约定

### 5.1 接口风格

- RESTful 风格，统一前缀 `/api`，例如：
  - `POST /api/auth/login` 登录
  - `GET /api/students?page=1&size=10&keyword=张` 学生分页列表
  - `POST /api/students` 新增 / `PUT /api/students/:id` 修改 / `DELETE /api/students/:id` 删除
  - `GET /api/scores/my` 学生查本人成绩

### 5.2 统一响应格式

```json
{ "code": 0, "msg": "success", "data": { } }
```

- `code = 0` 成功；非 0 为业务错误码（如 1001 参数错误、2001 用户名或密码错误、401 未登录、403 无权限）

### 5.3 鉴权方案

- 登录成功 → 后端用 jwt-cpp 签发 Token（payload 含 `uid`、`role`，有效期 24h）
- 之后所有请求经 Drogon `JwtFilter` 校验 Token → `RoleFilter` 校验角色权限（对应权限矩阵）
- 敏感字段（密码）BCrypt 加密入库

### 5.4 跨域方案

- 开发期：Vite 代理 `/api` → `http://localhost:8080`
- 生产期：Nginx 同域反代，天然无跨域问题

## 6. 部署方案

```
服务器（Linux 推荐 / Windows 亦可）
├── Nginx :80
│   ├── /          → Vue 打包产物 dist/（静态托管）

```

## 8. 选型风险与对策

| 风险 | 影响 | 对策 |
| ---- | ---- | ---- |
| C++ Web 开发资料少、上手门槛高于 Java/Node | 开发速度慢，调试成本高 | 严格按 Drogon 官方示例起步；先用"登录 + 学生列表"打通最小闭环，再批量复制模式 |
| Windows 下 vcpkg 编译 Drogon 依赖耗时 | 环境搭建受挫 | 使用 WSL2 统一开发/部署环境；或用预编译包 |
| C++ 内存安全问题（悬垂指针、越界） | 崩溃、漏洞 | 全程使用智能指针与 RAII；开启编译器 `-Wall` 警告；Drogon 异步接口避免裸 new |
| MySQL 驱动安装复杂 | 联调受阻 | 直接使用 Drogon 内置 MySQL 支持，按官方文档配置 `libmysqlclient` |

## 9. 结论

- **前端 Vue 3**：生态成熟、组件丰富，契合管理后台形态；
- **后端 C++17 + Drogon**：高性能、全功能框架，可满足鉴权/ORM/并发全部需求，选型成立；开发时以"官方示例 → 最小闭环 → 模块复制"的节奏推进以对冲学习曲线；
- **MySQL 8.0**：与 Drogon ORM 配合良好，事务与中文支持均满足需求。
