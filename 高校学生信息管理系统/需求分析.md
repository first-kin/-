## 1. 项目概述

### 1.1 项目背景
高校日常教学管理中，学生、教师、课程、成绩等数据分散且量大，传统人工/表格方式效率低、易出错、难汇总。本系统旨在提供一个统一的线上管理平台，实现学生信息、课程信息、成绩数据的规范化管理与快速查询。

### 1.2 项目目标
- 实现学生、课程、成绩信息的**电子化统一管理**
- 三种角色（管理员、教师、学生）**分权登录**，各取所需
- 提供**分页、搜索、统计**能力，提升查询效率
- 数据安全：密码加密存储、接口鉴权、操作留痕

### 1.3 系统范围
本系统为 Web 应用（B/S 架构），覆盖校园内教务信息的日常管理场景，不含排课算法、选课事务、财务缴费等复杂业务。

## 3. 功能需求

### 3.1 登录认证模块

**功能描述：** 系统唯一入口，校验用户身份并按角色跳转。

| 编号 | 需求点 | 优先级 |
| ---- | ------ | ------ |
| AUTH-01 | 用户名 + 密码登录，密码加密传输与存储（BCrypt） | 高 |
| AUTH-02 | 登录成功签发 Token（JWT），有效期默认 24h | 高 |
| AUTH-03 | 按角色（admin/teacher/student）自动跳转对应首页 | 高 |
| AUTH-04 | 连续输错 5 次锁定账号 10 分钟 | 中 |
| AUTH-05 | 退出登录清除 Token；未登录访问业务页自动跳回登录页 | 高 |
| AUTH-06 | 前端路由守卫 + 后端接口鉴权双重校验 | 高 |

**业务流程：** 输入账号密码 → 后端校验 → 通过则返回 Token 与角色信息 → 前端存 Token 并跳转；失败则提示“用户名或密码错误”。

---

### 3.2 学生信息管理模块

**功能描述：** 管理员维护学生档案，教师可查看所教班级学生。

| 编号 | 需求点 | 优先级 |
| ---- | ------ | ------ |
| STU-01 | 学生列表：分页展示（默认 10 条/页），支持按**学号/姓名/班级**模糊搜索 | 高 |
| STU-02 | 新增学生：填写学号、姓名、性别、出生日期、班级、联系电话、邮箱；创建学生时**自动生成登录账号** | 高 |
| STU-03 | 编辑学生：修改基本信息，学号不可修改 | 高 |
| STU-04 | 删除学生：二次确认；建议逻辑删除（可恢复） | 高 |
| STU-05 | 批量导入：支持 Excel 模板下载与批量导入，校验重复学号 | 中 |
| STU-06 | 批量导出：按筛选条件导出 Excel | 中 |
| STU-07 | 学生查看：仅能看到并修改自己的联系方式等允许字段 | 高 |

**数据校验规则：**
- 学号：唯一，格式“年级+专业代码+序号”（如 20240101）
- 手机号：11 位数字；邮箱：合法格式；性别：男/女 枚举

## 4. 非功能需求

| 类别 | 要求 |
| ---- | ---- |
| 性能 | 常规查询响应 ≤ 1s；支持 200 人同时在线 |
| 安全 | 密码 BCrypt 加密；JWT 鉴权；防 SQL 注入（参数化查询）；敏感操作记录日志 |
| 兼容性 | 主流浏览器 Chrome / Edge / Firefox 最新版本 |
| 易用性 | 界面简洁，常用操作 ≤ 3 次点击可达；表单有输入校验与错误提示 |
| 可维护性 | 前后端分离；统一响应格式 `{code, msg, data}`；统一异常处理 |
| 数据 | 数据库每日备份；删除采用逻辑删除 |
